# Lab 3：进程与 stride 调度

账号：zhengyihong0718。日期：2026-10-23。分支：ch5。

## 功能总结

将 get_time、mmap、munmap 迁移到进程地址空间，保留用户权限和跨页处理。spawn 从指定 ELF 直接创建子进程，建立父子关系并入队，不复制父地址空间。实现合法优先级设置和 stride 调度，按最小 stride 选取进程并累计与优先级成反比的步长。fork 保留未映射空洞，exec 重置堆边界。

## 实现与验证

进程可变信息通过当前 TCB 的内部借用访问；mmap/munmap 完成后释放借用，不跨调度持有。spawn 按用户页表逐字节读取有界、以零结尾的路径，拒绝非法地址、非 UTF-8 或无效程序名；新进程使用独立地址空间、PID、内核栈和初始上下文。子进程记录弱父引用，父进程记录子进程强引用，以复用退出、收养及 waitpid 的既有回收机制。

调度器在线性扫描就绪队列后取出 stride 最小者，同值保持原队列顺序。步长为 `max(2^32 / priority, 1)`，下限避免极大合法优先级整数除法得到零而使调度位置永久不变。新进程 stride=0、priority=16，set_priority 对小于 2 的参数返回 -1，否则设置并返回原参数。stride 使用 u64 回绕加法，以差值的有符号解释判断环形先后，避免溢出后简单数值比较造成倒序。

从上一章迁移时保留本章的进程框架，没有合并整条章节分支。fork 只复制各区域实际拥有的页，不根据包含空洞的外接区间重建全部页；父子帧分别分配，修改子页不会改变父页。exec 在替换映像时同时重置 heap_bottom/program_brk，避免沿用旧映像的堆地址。

实际验证：Windows Rust 1.98.1 主机测试直接包含真实 manager.rs，替代不可在宿主执行的 TCB 外壳和锁，先观察 FIFO 模板在比例和回绕测试中失败，修改后 3/3 通过。另有直接包含实际地址、页表与 MemorySet 源码的 2/2 测试，核验 fork 的空洞、帧独立和内容复制，以及解除后重新映射的权限。主机用页对齐内存模拟物理帧，不等于运行了 RISC-V MMU。完整内核、spawn、fork/exec 与历史测例的兼容性以该提交的官方 Linux Actions 为准；报告提交时不预报官方成绩。

## 问答：stride 算法

### 8 位溢出的例子

p1=255、p2=250 时先选 p2。若按 8 位无符号运算加 10，p2 变成 4；普通数值最小比较又选 p2，而不是理论上应该轮到的 p1。这是环形计数与线性整数顺序不一致。调试构建若使用普通加法还可能直接报溢出，需显式定义回绕语义或改用归一化方案。

### 为什么差值有界

在题设的固定可运行进程集合、初始 stride 相同、严格每次只给最小者增加步长的条件下，每个 pass 至多 BigStride/2。更新最小者后，它至多高于更新前最小值 BigStride/2，而其他进程原本也在这一范围内；新的最小值不会下降。因此用归纳法可知全体最大与最小之差不超过 BigStride/2。新进程动态加入并把 stride 置零、长期阻塞后重新加入等情形会改变这些前提，不能无条件套用这个证明；本实验遵循课程要求的新进程初值。

### 带回绕的比较器

对差值始终小于计数模长一半的两个 u64 值，`a.wrapping_sub(b) as i64 < 0` 表示 a 在环形时间线上早于 b。题目中 8 位的 125 与 255 相差 126，125 在 255 之后；129 与 255 的差值跨半圈，按该规则 129 在 255 之前。这些先后关系与单纯比较无符号数不同。

BinaryHeap 默认弹出按 Ord 最大的元素。若要它弹出实际最早的 stride，必须反转上述先后顺序，或在常规环形键外使用 Reverse；不能把“数值较小”和“堆优先级较大”混为一谈。例如其 PartialOrd 可写为：

```rust
fn partial_cmp(&self, other: &Self) -> Option<core::cmp::Ordering> {
    use core::cmp::Ordering;
    let order = match (self.0.wrapping_sub(other.0) as i64).cmp(&0) {
        Ordering::Less => Ordering::Greater,
        Ordering::Equal => Ordering::Equal,
        Ordering::Greater => Ordering::Less,
    };
    Some(order)
}
```

完整可用的堆键还应实现一致的 Eq/Ord；题设假定 stride 不相等，但实际系统会出现相等值，不能照搬永远返回 false 的 PartialEq 到通用容器中。当前实现使用就绪队列扫描，比较的是实际先后关系，没有 BinaryHeap 的反序问题，并对同值保留先入队者。
