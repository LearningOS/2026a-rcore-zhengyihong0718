# 第六章实验报告（含第七章问答）

账号：zhengyihong0718。日期：2026-10-23。分支：ch6。

## 功能总结（200字以内）

实现 fstat、linkat 和 unlinkat。多个目录项可以指向同一 inode，fstat 返回设备号、inode 编号、类型及当前链接数。删除目录项后复用空槽；最后一个链接删除且所有打开句柄释放时，回收 inode 和全部直接、间接数据块。已打开的文件在 unlink 后仍能读写，直到最后句柄关闭才允许复用 inode。fstat 支持跨页输出并验证用户缓冲区写权限。

## 设计说明

本章保留本账号 ch5 的 get_time、mmap/munmap、fork 空洞复制与 stride 调度逻辑，并适配当前框架的 MMIO 和文件描述符表。spawn 从文件系统读取目标 ELF 而非静态应用数组，创建独立地址空间，克隆父进程的文件 Arc 以继承打开文件描述与偏移；exec 重置新映像的堆边界。报告累计保留 lab1–3。迁移后的实际 MemorySet 源码通过 2/2 主机测试，完整历史测例兼容性仍交官方 Actions 验证。

easy-fs 保持原有磁盘 inode 布局不变。当前文件系统只有平坦的根目录，因此根目录中指向目标 inode 的有效目录项数量，就是硬链接数。查询时扫描根目录，避免更改已有镜像格式；文件系统重新打开后也能从目录项恢复正确的 nlink。查询的时间复杂度为 O(N)，其中 N 为根目录的目录项槽数。

内存中按 inode 编号记录存活的 VFS Inode 句柄数量；同一 Arc 的克隆不重复计数，独立的 find/open 获得新句柄。查找和计数增加在同一个文件系统锁内完成。unlink 清空相应目录项，随后检查链接数和句柄数。最后一个句柄的 Drop 再次检查这两个条件，只有均为零时才清空数据块、回收间接索引块，并释放 inode 位图。这样旧文件描述符不会读写到复用 inode 的新文件。

空目录项以空名称标记，find 和 ls 跳过空槽；新增文件和链接优先使用空槽，避免反复删除产生无限目录增长。保留根目录已分配的数据块，inode/data 回收针对被删除的普通文件。

File trait 提供返回 Option<Stat> 的 stat 方法，普通 OSInode 返回元数据，控制台等非磁盘对象返回 None。sys_fstat 验证 fd 和整个用户输出区域，再按页拷贝 80 字节的 Stat；pad 全部清零。用户路径最长 27 字节加 NUL，拒绝无效地址、空名、过长名称及当前平坦目录不支持的路径。

## 第六章问答

**root inode 起什么作用？其内容损坏会怎样？**

root inode 是文件系统目录树的入口，在 easy-fs 中固定为 inode 0，记录根目录的类型、长度和保存目录项的数据块位置。目录项把文件名映射到 inode 编号，因此查找、创建、列目录和本实验的链接计数都以它为起点。

如果 root inode 的长度或块指针损坏，内核就可能读不到目录项、读取错误数据块，甚至在断言中止或错误修改其他块。普通文件的数据块可能仍然存在，但正常路径查找已经失去入口。本实现从根目录统计 nlink，根目录损坏还可能使链接计数错误并造成错误回收。修复需要可信备份、日志或离线检查与重建，不能仅靠重新创建一个空根目录恢复原文件名。

## 第七章问答

**1. pipe 的实际应用。**

例如 `cat report.txt | wc -l`：shell 建立管道，把 cat 的标准输出连接到管道写端，把 wc 的标准输入连接到读端。cat 顺序读取文件并写入管道，wc 从管道读取并统计换行符数量。二者可以边产生数据边消费，无须中间临时文件。所有写端关闭后，读端读到 EOF 并结束统计。`wc -l` 统计换行符，若文件末尾没有换行符，结果可能比人眼认定的文本行数少一。

**2. 更易用的多进程通信机制。**

可以提供带名称或句柄的消息队列，由内核管理队列和阻塞等待。进程调用 create/open 获取某个服务的队列句柄，发送带有发送者、接收者或主题、类型、长度、请求编号及负载的消息。多个生产者可向同一服务队列发送，接收方按目标或主题接收；回复携带请求编号并发送到调用方的回复队列。这样每个服务或进程维护少量队列即可，无须为每一对进程建立管道。

内核检查访问权限和消息长度，对队列容量设置上限。队列满时发送者阻塞或收到“稍后重试”，队列空时接收者阻塞；关闭或进程退出唤醒相关等待者，防止永久挂起。消息边界由内核保存，避免字节流中自行拆包；共享内存可以承载大数据，队列只传递控制信息和经过权限验证的共享区句柄。
